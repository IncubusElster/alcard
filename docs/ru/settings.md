# Настройки и конфигурация системы

**Язык:** Русский · [English](../en/settings.md)

> Область: текущее дерево исходников · Обновлено: 2026-11-22

`alcard-settings` — рабочее приложение настроек на Ratatui. Оно сохраняется в Graphics, Graphics Minimal и Console. В графическом меню **Настройки** запускают этот же TUI через desktop entry с `Terminal=true` и Foot. Отдельный графический frontend Settings запланирован; существующее окно polkit является агентом авторизации, а не этим приложением.

```sh
alcard-settings
alcard-settings --help
```

`alcard-settings --hello` — защищённый мастер первого запуска, описанный в [установке](installation.md). Это не способ сбросить или перенастроить завершённую установку. TUI требует интерактивный терминал для ввода и вывода; компактная цель — 40×21.

## Навигация

| Контекст | Клавиши | Результат |
| --- | --- | --- |
| Список | Up/Down или Tab | Выбрать строку |
| Список | Enter/4; Space/5 также активирует выбранную строку | Открыть, отредактировать, выбрать значение или выполнить действие строки |
| Список | 6 | Обновить текущую страницу |
| Список | Esc/8, Backspace или Shift+Tab | Назад; выход на верхнем уровне |
| Текстовое/парольное поле | Обычные символы, цифры 4–8 и Space | Ввод текста, а не действия софткнопок |
| Текстовое/парольное поле | Backspace | Удалить последний символ |
| Текстовое/парольное поле | Enter / Esc | Отправить / отменить изменение |
| Выбор значения | Up/Down/Tab, затем Enter/4 | Выбрать значение |
| Подтверждение | Enter/4 / Esc/8 | Подтвердить / отменить |

Нижняя строка описывает текущий контекст. В TUI Tab перемещает фокус; это не алиас слота 6 графической Shell. Привязки F3/7 Shell также не задают сочетания TUI. Ctrl+C завершает работу или запрашивает отмену там, где она поддержана. Во время внешнего запроса авторизации Ctrl+C принадлежит foreground-команде; затем TUI восстанавливает свой терминальный экран.

Чтение состояния и большинство операций служб выполняются вне цикла рендеринга. Из ожидающего чтения можно выйти назад. Подключение Wi-Fi и сопряжение Bluetooth имеют явные пути отмены; Back не обещает отменить любую уже отправленную системную операцию. Ошибка или отсутствие службы показываются явно, без выдуманного состояния «выключено».

Строки «Версия Alcard» нет. Создание аккаунта и настройка паролей относятся к первому запуску; переключение установленного режима, factory reset и пакетный менеджер не являются текущими функциями Settings.

## Система, язык и клавиатура

Hostname допускает 1–63 латинские ASCII-буквы, цифры или дефисы, без дефиса в начале и конце. Backend меняет текущее имя устройства и `/etc/hostname`.

Системный язык выбирается между английским, русским и испанским. Backend записывает проверенную локаль в `/etc/profile.d/alcard-locale.sh`. После операции Settings обновляет язык и запрашивает перечитывание настроек установленной Shell текущего пользователя. Общий загрузчик Shell учитывает сначала явный CLI locale, затем системный язык, затем прежнее пользовательское поле locale либо окружение/default. Обычные Settings предлагают одну настройку языка системы, без конкурирующих языковых переключателей приложений. Уже работающим сторонним программам может понадобиться новый вход/запуск для наследования окружения.

Settings, Shell, locker и polkit-agent используют общий `alcard_l10n::Locale`. Автоматический выбор берёт первую непустую переменную в порядке `LC_ALL`, `LC_MESSAGES`, `LANG`, распознаёт поддерживаемые языковые префиксы без учёта регистра и выбирает английский для неподдерживаемого значения. Явный системный/CLI язык сохраняет приоритет. JSON-каталоги и подписи отдельных приложений сохраняют тексты EN/RU/ES.

Original US нельзя удалить, она остаётся первой. RU/ES/DE можно включать и выключать. В них меняются буквы, а исходный символьный слой сохраняется. Набор записан в `/etc/alcard-keyboards`; сгенерированные XKB-настройки — в `/etc/alcard/keyboard-xkb.env`. Несколько графических раскладок переключаются Alt+Shift после следующего входа. Загрузочная консоль остаётся US. На номерном Linux VT Settings могут временно загрузить одну из сохранённых консольных раскладок и записывают её в `/run/alcard-active-layout`; в эмуляторе терминала эта VT-строка не показывается. См. [шрифты и клавиатуру](fonts-keyboard.md).

## Дата и время

Часовой пояс — установленная IANA-зона, например `America/Montevideo`. Backend проверяет имя и файл зоны перед изменением `/etc/localtime` и `/etc/timezone`.

NTP использует установленную службу OpenRC: сначала `chronyd`, при её отсутствии — `ntpd`. Переключение меняет и запущенную службу, и регистрацию в default runlevel. Ручное локальное время имеет точный формат `YYYY-MM-DD HH:MM:SS`, проверяется через `date` и отклоняется, пока одна из NTP-служб включена или работает. Если существует `/dev/rtc0`, успешная ручная установка времени также записывает аппаратные часы в UTC.

## NetworkManager

NetworkManager управляет соединениями Wi-Fi/Ethernet, DHCP, сохранёнными профилями и сетевыми секретами в Hello и обычных Settings. Общий клиент использует фиксированный `/usr/bin/nmcli` с отдельными аргументами, без интерполяции командной оболочкой. Низкоуровневая реализация Wi-Fi относится к NetworkManager; Alcard больше не запускает рядом с ним самостоятельную схему `wpa_supplicant`/DHCP.

Страница сети показывает сохранённые профили, питание Wi-Fi при наличии устройства и интерфейсы Ethernet/Wi-Fi. Страница интерфейса позволяет активировать или отключить его и показывает доступные сведения GENERAL/IP4/IP6. Ближайшие Wi-Fi показывают SSID, сигнал и защиту; одинаковые SSID объединяются. Неподдерживаемые/скрытые пустые SSID не превращаются в выдуманные доступные сети. Если policy запрещает активный поиск, можно использовать доступный AP cache NetworkManager.

Для защищённой сети при уже достаточных правах TUI принимает маскированный пароль и передаёт его `nmcli --ask` через stdin. Если нужны повышенные права, строка подтверждает операцию, а нужный ввод получает терминальный запрос авторизации/nmcli. Пароли аккаунта и Wi-Fi не помещаются в аргументы команд. Ошибка показывается пользователю; успешный код завершения не является проверкой доступа к Интернету.

Сохранённые профили Ethernet/Wi-Fi выбираются по UUID. Страница профиля поддерживает:

- активацию и включение/выключение автоподключения;
- адрес IPv4 с префиксом, шлюз и IPv4 DNS;
- возврат к DHCP;
- удаление профиля после подтверждения.

Задание адреса выбирает ручной IPv4. Возврат к DHCP очищает ручные адрес/шлюз/DNS и возвращает автоматический DNS. После редактирования явно активируйте профиль, чтобы применить его к устройству. Сведения IPv6 видны, но полноценный редактор IPv6, VPN и enterprise Wi-Fi в этом UI не реализованы.

Upgrade hook импортирует только известный формат единственного Wi-Fi-профиля, который создавали прежние версии Alcard Hello. Он сохраняет исходные файлы, включает `dbus` и `networkmanager` и удаляет прежнее владение runlevel со стороны `networking`/самостоятельного `wpa_supplicant` для следующей загрузки. Нераспознанные старые данные отклоняются, а не угадываются. Это путь совместимости, а не текущий сетевой backend.

## Bluetooth

Settings используют BlueZ: питание, ограниченный поиск и действия устройств через `bluetoothctl`, а для сопряжения — отдельный D-Bus agent. Страница устройства показывает адрес, имя, paired/connected и соответствующие действия pair/connect/disconnect/remove. Удаление требует подтверждения.

Агент сопряжения поддерживает PIN, passkey и подтверждение числа, привязывает запросы к выбранному устройству и уникальному владельцу BlueZ, затем снимает регистрацию. Отмена запрашивает `CancelPairing`, но не обещает отозвать уже завершённое сопряжение. Сопряжение и подключение — разные операции. Отсутствие контроллера/службы и отказ прав показываются как недоступность. Совместимость с реальными Bluetooth-устройствами ещё требует приёмки.

Общая установленная конфигурация Bluetooth запрещает автоматическое включение адаптера (`AutoEnable=false`). Быстрые настройки Shell умеют показывать списки и переключать радио, но не содержат этот UI сопряжения; см. [рабочий стол](desktop.md).

## Экран, питание и звук

Settings показывают яркость, когда `brightnessctl` может прочитать подсветку, и ёмкость батареи из sysfs при её наличии. Привилегированное действие яркости TUI принимает 0–100%. Это отличается от быстрых настроек Shell, где относительная регулировка сохраняет ненулевую нижнюю границу. Установка яркости в ноль сама по себе не гарантирует автоматическую блокировку.

При установленной Shell страница позволяет менять сроки автоблокировки/гашения, пороги низкого/критического заряда и явно включать автоматический сон. Это политики Shell; само наличие пакета в Graphics Minimal не запускает их. Проверки, значения по умолчанию и защитные условия описаны в [питании и звуке](power-audio.md).

Звук использует PipeWire/WirePlumber текущего пользователя. Страница перечисляет Audio/Sink, по возможности отмечает основной выход, принимает громкость 0–100%, переключает mute и выбирает sink по умолчанию. ID выхода сверяется со свежим списком. Полноценного редактора маршрутов/профилей нет. Аудиостек запускает Graphics-сессия; Minimal и Console автоматически его не запускают. Их страница звука зависит от отдельно доступных служб и не запускает daemon скрытно. Громкость — программный регулятор, а не измеренный уровень динамика и не гарантия усиления кодека.

## Preferences и авторизация

Оформление и политики Shell сохраняются в `$XDG_CONFIG_HOME/alcard/shell.toml`, обычно `~/.config/alcard/shell.toml`. Запись использует файловую блокировку, проверяет весь кандидат, создаёт приватный временный файл, атомарно заменяет целевой и синхронизирует каталог. Ошибка существующей конфигурации показывается, а не затирается как будто файл был корректным. Успешная запись посылает SIGHUP только процессам `/usr/bin/alcard-shell` текущего пользователя; pidfd защищает от повторного использования PID.

Системные изменения используют allowlist root-only `alcard-setupd --setting KEY VALUE`. Этот путь не выполняет создание аккаунта первого запуска. TUI временно выходит из alternate screen/raw mode для doas или su; операции NetworkManager аналогично запрашивают повышение, когда этого требуют сообщённые им права. Разрешение операции по-прежнему проверяет целевой backend. Пользовательские значения передаются отдельными аргументами; фиксированная обёртка su сохраняет их границы.

В общем core пока есть терминальный адаптер команд. Будущий GUI должен добавить подходящий графический адаптер авторизации вокруг тех же операций, используя существующий polkit. Ему не следует дублировать правила настроек или запускать TUI как свой функциональный backend. Границы процессов описаны в [безопасности](security.md).
